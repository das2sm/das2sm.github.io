Real-time traffic sign detection on a $150 board

February–March 2026  ·  ACSI Laboratory, Feng Chia University
YOLOv4edge deploymentquantizationRK3588

The goal was a clean, self-contained proof: take a model from training all the way to real-time inference on hardware that costs less than a textbook, with nothing hand-waved in between.

Training

I trained a YOLOv4 model on a 15-class traffic sign dataset. The first run was a clear failure — 17.96% mAP@0.5. The model was learning something, just nowhere near usable. I worked through the standard checklist — data loading, label format, anchor configuration, learning rate — before isolating the actual cause: SGD with weight_decay=5e-4 was preventing convergence at this dataset's scale.

Switching to Adam resolved it immediately. The second run cleared 80% mAP@0.5, and with further tuning the model settled around 95% mAP@0.5.

Takeaway

The optimizer isn't a hyperparameter you set once and forget — it's a modeling decision with the same weight as the architecture itself.

Deployment pipeline

Training a model that runs well on an RTX 3090 solves a different problem than running it at real-time speed on a single-board computer. I built the full conversion chain:

PyTorch (.pth) ↓ export
ONNX (.onnx) ↓ convert + quantize
RKNN (.rknn) — INT8 ↓ deploy
Orange Pi 5 Ultra — RK3588 NPU

Three decisions did most of the work:

  • INT8 quantization — the RK3588's NPU is dramatically faster at integer arithmetic than floating point, and the accuracy cost was small enough to be worth it.
  • 3-core NPU inference pool — the chip exposes three separate NPU cores. Running a pool across all three, instead of serializing on one, produced most of the total throughput gain.
  • Vectorized NumPy post-processing — once the NPU is fast, naive Python-loop non-max suppression and box decoding becomes the actual bottleneck. Rewriting it in vectorized NumPy kept the CPU from throttling a pipeline the NPU was ready to run much faster.

It's a concrete demonstration that meaningful ADAS-relevant perception doesn't require GPU-class compute — which matters a great deal for cost-sensitive deployment.
