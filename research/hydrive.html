Privileged Occupancy Filtering for Fixed-Vocabulary End-to-End Driving

This was my main research project in Taiwan. I wanted to know whether perfect occupancy information could make an end-to-end planner safer if the only allowed intervention was to reject bad trajectory proposals and choose another one the planner had already produced.

What I was testing

SparseDriveV2 produces up to 1,024 trajectory proposals and selects one using learned scores. I added a filter at that selection step. For every proposal, the filter checks whether the ego vehicle's future footprint intersects occupied space. If a clear proposal exists, it can be selected instead. The filter does not generate trajectories and it does not have an emergency-braking mode.

I used CARLA ground-truth actor state as the occupancy source. That was deliberate: the point of this experiment was to remove perception error and ask whether better information is useful at all when the planner is still restricted to its original proposal set.

Current-frame vs. temporal occupancy

I evaluated two versions of the filter. The current-frame version applies the scene at time t to every future waypoint. The temporal version propagates moving actors with a constant-velocity model and checks occupancy at the corresponding future waypoint times. The current-frame arm matters because freezing a moving car in place can turn it into a fake permanent wall.

The experiment took a few tries to get right

The early campaigns were useful, but I did not use them as final evidence. A 15-route dev run showed a large apparent improvement that mostly disappeared on the full test set. A later campaign looked better, but every arm ran in the same order on one long-lived CARLA process. That made treatment and execution position inseparable, and CARLA was clearly behaving differently depending on process history.

I rebuilt the final evaluation around the problems I had seen: three seeds, a fresh CARLA server and evaluator for every job, deterministic route-specific Traffic Manager seeds, and balanced ordering of all six arm permutations. Driving failures were kept as outcomes; only actual software failures were rerun.

Final campaign

185 routes × 3 seeds × 3 arms = 1,665 simulation jobs. Each arm ran 555 jobs.

Confidence intervals are 95% intervals from a 20,000-resample route-family cluster bootstrap. Temporal filtering reduced collision-route incidence by 4.0 percentage points, with the effect pointing in the same direction at all three seeds, while the pre-specified route-completion guardrail was satisfied. Driving Score and Success Rate also improved.

The temporal-versus-current-frame contrast did not resolve at 95% confidence, so I would not claim that this experiment proves temporal propagation itself is the whole reason for the improvement. What the results do support is that the temporal filter improved the planner relative to the unmodified baseline under this evaluation.

One useful failure mode

Filtering cannot help when every proposal is bad. I saw routes where all of SparseDriveV2's available trajectories intersected occupancy. In those cases the problem is no longer choosing the wrong proposal; the proposal set simply does not contain a safe option. That limitation is important because the occupancy used here is privileged simulator state — effectively an upper bound on what a perception system could provide to this filter.

An upstream benchmark bug

While checking Fail2Drive's evaluation code for the final campaign, I found a scenario-name resolution mismatch that could silently skip some test scenarios. The evaluator could keep running without throwing an error, so a route might finish even though the intended hazard never spawned. I reported it to the authors and the fix was merged upstream. My final campaign also checked scenario initialization and aborted instead of accepting a silently incomplete evaluation.

Limitations

  • The occupancy source is privileged CARLA state, not a learned perception model.
  • The occupancy representation is 2D with a fixed vertical slab.
  • Dynamic actors are propagated with constant velocity and fixed yaw.
  • The study covers one planner, one benchmark, 185 routes, and three seeds.
  • The filter can only reject and reselect; it cannot generate a new trajectory or brake independently.
